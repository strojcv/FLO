# FLO — потоковый органайзер и копилка для Hermes

**FLO** (Flow Life Organizer) — официальное название проекта.

**Установка** (на сервере с Hermes, под его пользователем):

```bash
git clone https://github.com/strojcv/FLO.git ~/flows-organizer
bash ~/flows-organizer/install.sh
```

На вопрос «Сделать? [Д/н]» — «да». Дальше `hermes gateway restart`, в Telegram `/new` и `/list`.
По шагам, голосовые, обновление — [readme-install.md](readme-install.md).

Голосом или текстом в Telegram ведёшь **потоки** работы. Hermes помнит, где ты остановился,
ведёт задачи по точкам работы, хранит комментарии к потокам (всё вперемешку: мысли, идеи, выводы), ведёт календарь с напоминаниями
и подсказывает, что заброшено.
Отдельно — **копилка**: телефоны, адреса, контакты и любые факты вне работы, с автотегами.
Всё лежит в markdown-файлах: их видит Obsidian на компьютере.

## Как устроено

```
~/brain/
  ПОТОКИ.md                  оглавление (собирает сервер, руками не править)
  _теги.md                   словарь тегов
  _inbox/voice/              расшифровки голосовых до привязки к потоку
  _inbox/заметки.md          мысли без потока
  _audio/                    исходное аудио (только на сервере, в git не идёт)
  _templates/                шаблоны для ручного создания в Obsidian
  flows/reklama/
    _поток.md                главный файл: приоритет (основной/фоновый), статус, комментарии потока (новые сверху)
                             + оглавление точек с выжимками (собирается само)
    2026-10-20.md            точка (завершена): Задачи (сделанные с ✓) / Контекст
    2026-10-23.md            точка (открыта — текущая, у потока она одна)
    sources/2026-10-23-021512.md   расшифровка голосовой с таймкодами
  календарь/
    КАЛЕНДАРЬ.md             всё по времени (собирается само)
    2026-10-27-zapusk-reklamy.md   событие: when, remind, flow (если по потоку)
  копилка/
    КОПИЛКА.md               картотека: теги со ссылками + все записи по датам (собирается сама)
    2026-10-23-1218.md       одна запись — один файл, имя = дата и время сохранения
    _files/                  вложения (фото визитки, PDF)
```

- **Источник правды — файлы точек и событий.** `ПОТОКИ.md`, оглавления, сводки и напоминания
  вычисляются из них.
- **Жизнь точки.** У потока одна открытая точка — новые задачи и контекст пишутся в неё сверху списка.
  Комментарии — одни на весь поток, новые сверху; идеи и выводы — тоже просто комментарии. Сделанная задача —
  кнопка `/xK`: пропадает с экрана, в файле остаётся с ✓. «Начинаем новую точку» — текущая
  завершается, открывается новая (с датой этого момента), невыполненные задачи переезжают
  в неё. Завершённые точки — история: листаются кнопками `/prev` `/next`.
- **Указатель** стоит только на точке потока или нигде: `/list` его снимает. `/new` из меню
  только чистит контекст и ничего не присылает; кнопки тоже чистят контекст, но присылают свой экран. `/point` (меню) возвращает к
  последней точке, `/back` — из комментариев в карточку. Все кнопки работают скриптом, без нейросети.
- **Нейросеть не пишет файлы руками** — только через `flows.py`. Скрипт ставит даты, находит
  поток по словоформе («по рекламе»), обновляет оглавление и синхронизирует git.
- **Длинная голосовая** расшифровывается скриптом `flows_stt.py`: аудио и полный текст с
  таймкодами сохраняются сразу, ещё до нейросети. Hermes получает текст с меткой
  `[voice:<id>]`, привязывает исходник к потоку и раскладывает мысли по разделам.
  Голосовые короче минуты считаются командами и не сохраняются.
- **Напоминания** — фоновая задача Hermes без нейросети: токены не тратятся. Утренней сводки нет (отказались).

| Файл | Куда ставится | Зачем |
|---|---|---|
| `hermes-scripts/flows.py` | `~/.hermes/scripts/` | вся логика |

## Установка на сервер

Всё делается **от пользователя, под которым работает Hermes**. Нужен Python 3.9+, git, ffmpeg.

**1. Скопировать пакет и запустить установщик**

```bash
scp -r flows-organizer user@server:~/
ssh user@server
bash ~/flows-organizer/install.sh          # хранилище будет в ~/brain
```

**2. Расшифровка — твой уже установленный Whisper.** По умолчанию `flows_stt.py` вызывает
Python из `~/.openclaw/tools/venv` (там стоят openai-whisper и faster-whisper):
сначала `openai-whisper` с моделью `small`, при сбое — `faster-whisper` с `base`. Модели берутся
из `~/.cache/whisper` и `~/.cache/huggingface` — ничего не ставится и не скачивается.
Путь к venv и порядок движков — `stt_venv_python` и `stt_engines` в `~/.config/flows/config.json`.
Русская модель **GigaAM v3** (ONNX int8, ~225 МБ, быстрая, с пунктуацией): `bash ~/flows-organizer/setup-gigaam.sh`
— ставит её в отдельный venv `~/.venvs/gigaam` и делает первым движком, Whisper остаётся запасным.
Облачный вариант (Groq / OpenAI) — `"stt_backend": "groq"` и ключ в `~/.config/flows/secrets.env`.

**3. Подключить расшифровку к Hermes.** Это делает `install.sh`: если голосовые ещё не идут в
органайзер, он покажет это вместе с двумя другими настройками (`/new` без «точно?», напоминания)
и спросит «Сделать? [Д/н]». На «да» — копия `~/.hermes/config.yaml.bak-flows-<дата>` и блок `stt`
через `hermes config set`. Отдельно: `bash ~/flows-organizer/setup-hermes.sh`. Откат — вернуть копию и
`hermes gateway restart`. `timeout: 3600` — запас на записи до 30 минут на CPU.

**4. Новый SOUL.md и перезапуск.**

```bash
cp ~/.hermes/SOUL.md ~/.hermes/SOUL.md.bak-flows
cp ~/flows-organizer/SOUL.md ~/.hermes/SOUL.md
hermes gateway restart
```

**Убрать старую архитектуру.** Старый SOUL.md создавал отдельные задачи cron на каждое
напоминание и ежедневную проверку с нейросетью — они остались и будут работать дальше.
`hermes cron list` → старые задачи удали: `hermes cron remove <id>`. Загляни в
`~/.hermes/memories/MEMORY.md`: строки про `~/assistant/`, архив, schedule.md убери.
Папку `~/assistant/` не удаляй — её записи можно перенести в копилку.

**5. Фоновые задачи.** Сначала в чате с ботом отправь `/sethome`, чтобы Hermes знал, куда
слать сообщения. Задачу заводит `install.sh` (тот же вопрос «Сделать?», что в шаге 3); вручную:

```bash
hermes cron create "every 1m" --no-agent --script flows_remind.py --deliver telegram --name flows-reminders
hermes config set cron.wrap_response false
```

`cron.wrap_response false` обязателен для красивых push-уведомлений: иначе Hermes ставит над
каждым сообщением шапку «Cronjob Response: flows-reminders», и в уведомлении видна она, а не
название точки. Настройка общая — шапка пропадёт и у других твоих фоновых задач.

**Как работают напоминания.** Шлюз Hermes раз в минуту запускает `flows_remind.py`. Скрипт
смотрит поле `remind` у событий в `календарь/`: время не пришло — молчит (в Telegram ничего),
пришло — печатает текст, и Hermes отправляет его как есть. Первая строка — что и когда
(«Запуск рекламы — сегодня в 19:00»), её и видно в push; для потока ниже — «Начать с: …»
(задачи открытой точки). Каждое напоминание приходит один раз; опоздавшие больше чем на
12 часов (сервер лежал) пропускаются. GitHub проверяется не чаще раза в 5 минут. Прошедшие
события закрываются сами через 3 часа.

**Ответы на напоминание** («отложи на 15 минут», «перенеси на четверг», «отмени») работают,
только если Hermes видит текст напоминания в истории чата. Для этого:
`hermes config set cron.mirror_delivery true` и `hermes gateway restart`. Затем ответь на
напоминание «отложи на 5 минут» — если Hermes понял, о каком событии речь, всё работает; тогда
включи подсказку в конце напоминаний: `"remind_reply_hint": true` в `~/.config/flows/config.json`.
Если не понял — говори с названием: «отложи запуск рекламы на 15 минут».

Время в расписании cron — **по часам сервера**. Проверь `timedatectl`: если сервер в UTC,
а ты в Москве (UTC+3), то «9 утра» — это `0 6 * * *`. Сам органайзер считает даты по
`timezone` из `config.json`.

Недельный обзор с анализом (тратит токены, раз в неделю) — в `snippets/weekly-review-cron.md`.

**6. Проверка**

```bash
python3 ~/.hermes/scripts/flows.py new-flow "Тест"
python3 ~/.hermes/scripts/flows.py new-point тест --title "Проверка"
python3 ~/.hermes/scripts/flows.py status
python3 ~/.hermes/scripts/flows.py set тест --status closed
```

Затем в Telegram: наговори голосовую на 1–2 минуты про любой поток и проверь, что ответ
начинается с `📍` и в `~/brain/flows/<поток>/sources/` появилась расшифровка.

## Синхронизация с Obsidian через GitHub

**На сервере:**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/brain_deploy -N ""
cat ~/.ssh/brain_deploy.pub
```

На GitHub создай **приватный** репозиторий `brain` → Settings → Deploy keys → Add,
вставь ключ и отметь **Allow write access**. Потом:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github-brain
  HostName github.com
  User git
  IdentityFile ~/.ssh/brain_deploy
EOF
git -C ~/brain add -A && git -C ~/brain commit -m "Старт"
git -C ~/brain remote add origin git@github-brain:<твой-логин>/brain.git
git -C ~/brain push -u origin main
```

И включи автосинхронизацию: в `~/.config/flows/config.json` поставь `"git_autosync": true`.
Теперь перед каждым изменением сервер делает `pull`, после — `commit` и `push`, а задача
напоминаний подтягивает правки раз в 5 минут. Поэтому событие с напоминанием можно
добавить прямо в Obsidian.

**На компьютере:**

1. Клонируй репозиторий в папку и открой её в Obsidian как хранилище.
2. Установи плагин **Git** (Community plugins). В настройках: включи pull при запуске,
   автоматический pull каждые 5 минут и автоматический commit-and-sync каждые 5 минут.
3. Включи встроенный плагин **Templates**, папка шаблонов — `_templates`.
4. По желанию: плагин **Dataview** и файл `snippets/obsidian-Панель.md` в корень хранилища —
   таблицы потоков, календаря и последних точек.

**Ручная работа в Obsidian.** Дописывать в точки можно свободно: строка вида
`- 2026-10-25: текст` в нужном разделе. Новая точка — файл `ГГГГ-ММ-ДД.md` в папке потока
из шаблона «Точка» (заполни `flow:` и `title:`). Событие — файл в `календарь/` с полями
`type: event`, `title`, `when: 2026-10-27T19:00`, `status: active` и, если нужно,
`remind: 2026-10-27T18:30` (и `flow: <папка потока>`, если по потоку).

**Конфликты.** Если одну и ту же строку поменяли и на сервере, и в Obsidian между
синхронизациями, Hermes сообщит о конфликте. Ответь, какую версию оставить, или выполни
`flows.py sync --prefer server` / `--prefer pc`. Дописывание новых строк конфликтов не даёт.

## Как пользоваться (фразы для Telegram)

| Говоришь | Что происходит |
|---|---|
| «Покажи потоки» | все актуальные потоки: на чём остановились и что предстоит |
| `/list` (кнопка в конце каждого ответа) | каталог основных потоков одним списком, пронумерован, без задач и без кружков; поток, где ты был, выделен 👉; указатель снят |
| `/background` (ссылка «Фоновые потоки (N)» внизу каталога) | фоновые потоки |
| `/2` (номер в каталоге) | карточка открытой точки: ⚡ в начале шапки (у фонового потока справа от названия «· фоновый»), дата, `/comments (N)`, задачи; внизу `◀ /prev`; указатель на ней |
| `/point` (команда, в нижний ряд не выводится) | точка, на которой стоит указатель (вернуться к ней из каталога, комментариев, календаря); нажать ещё раз, уже на карточке, — последняя точка потока |
| `/prev` / `/next` | соседняя точка потока (в завершённых сделанные задачи — с ✓) |
| `/comments` (под датой) | комментарии всего потока, новые сверху; под каждым — `/f` (раскрыть) и `/x` (удалить комментарий); `/back` (в строке «Комментарии») — назад к карточке |
| `/done (N)` (под задачами) | та же карточка, внизу раскрыт список выполненных задач с ✓ впереди |
| `/f1` (панель под задачей или комментарием: «/f1  ▫️  /x1», первая кнопка) | раскрыть только эту запись полностью («Заголовок — весь текст»); ещё раз — свернуть. Есть только у записей, где текст длиннее заголовка |
| `/x1` (вторая кнопка панели, после ▫️; всегда на одном месте — нечего раскрывать, на месте `/f1` прочерк: «——  ▫️  /x1») | задача выполнена: в файле осталась с ✓, на экране её больше нет; на экране комментариев — комментарий удалён |
| `/calendar` (первая в нижнем ряду) | календарь: события с датой по времени (в две строки: дата и время, ниже что сделать; сегодняшние — с ⚡ сразу после номера; ⏰ и когда напомнит — где есть напоминания), ниже «📌 Без даты»; `/x1` рядом с событием убирает его |
| «Верни задачу про рассылку» | скрытая задача снова видна |
| `/new` (меню Telegram) | только очистка контекста, в чат ничего не приходит |
| «Продолжаем работать в рекламе» | указатель на открытую точку «Рекламы», сводка: прошлая точка + задачи |
| «Что по рекламе?» / «На чём я остановился в рекламе?» | прошлая точка (задачи, сделано), свежие комментарии потока + задачи на сейчас |
| «3» (после списка точек) | детали точки №3 |
| «Новый поток: продающие звонки» / «новый фоновый поток: гитара» | создаёт основной / фоновый поток |
| «Начинаем новую точку» / «начинаем новую позицию» | текущая завершается, новая открывается, невыполненные задачи переезжают |
| голосовая до 30 минут | сохраняет исходник, раскладывает по разделам по тем же правилам |
| «Комментарий: …» / «Идея: …» / «Задача: …» | в поток под указателем: задача — в открытую точку, комментарий и идея — в начало комментариев потока (идея — обычный комментарий) |
| «Вывод: …» | комментарий потока (отдельных выводов нет) |
| «Это не задача, а комментарий» | переносит последнюю запись |
| «Напомни в пятницу в 15 пойти к стоматологу» | событие в календаре с напоминанием |
| «Запиши в календарь …» | событие; если есть дата — Hermes спросит, напомнить ли |
| «Запиши в календарь: купить резину» (без даты) | событие без даты — внизу календаря |
| «Верни в календарь резину» | убранное `/x` событие снова в календаре |
| «Что у меня ближайшее?» / «Покажи календарь» | тот же экран, что `/calendar` |
| «Отложи на 15 минут» / «перенеси на четверг» / «отмени» | ответ на напоминание |
| «Поставь звонки на паузу» / «Закрой поток сайт» | статус потока |
| «Мысли про продажи из всех потоков» | поиск по тегу #продажи |
| «Что лежит во входящих?» | неразобранные голосовые и заметки |

Приоритетов два: **1 — основные** (видны сразу в `/list`) и **2 — фоновые** (за кнопкой `/background`).
«Давно не трогали» (⚠) срабатывает для основных через 7 дней, для фоновых — через 14 (меняется в
`stale_days` в `config.json`).

## Копилка

Говоришь «сохрани телефон стоматолога в Палермо, доктор Гомес, 11 5555 1234» — Hermes в том же
ходе придумывает 2–5 тегов (что: `стоматолог`, категория: `медицина`, место: `буэнос-айрес`),
нормализует телефон и вызывает `facts.py save`. Скрипт создаёт файл `ГГГГ-ММ-ДД-ЧЧММ.md`,
обновляет картотеку `КОПИЛКА.md` и, если тег новый, подсказывает похожие существующие
(`#стоматология` → уже есть `#стоматолог`) — Hermes сам приводит к одному.

Отдельная нейросеть или фоновая задача для тегов не нужна: Hermes и так читает сообщение,
4 тега — это десяток токенов. Запуск отдельного агента стоил бы тысячи.

Поиск: «телефон стоматолога» → по тегу; «что у меня из медицины» → тег `медицина`, а если мало —
Hermes смотрит список тегов (`facts.py tags`, одна строка) и добирает по смыслу: `стоматолог`,
`лор`. «Гомес» → полнотекстовый поиск ripgrep. Файлы целиком Hermes не читает — скрипт отдаёт
только найденное.

| Говоришь | Что происходит |
|---|---|
| «Сохрани телефон …» / «Запиши адрес …» | запись с тегами |
| «Какой телефон у стоматолога?» | поиск по тегу |

## Обслуживание

- Самопроверка пакета (во временной папке, данные не трогает): `bash tests/run_tests.sh`.
- **Обновление** — тот же `install.sh`: загрузить новую папку в `~/flows-organizer/`, запустить
  `bash ~/flows-organizer/install.sh`, затем `/restart` и `/new` в Telegram. Данные не трогаются;
  подробно — `readme-install.md`.

- `python3 ~/.hermes/scripts/flows.py --help`, `python3 ~/.hermes/scripts/facts.py --help` — все команды.
- Аудио копится в `~/brain/_audio/`: 20 минут в m4a — несколько мегабайт.
  Чистить по желанию — расшифровки останутся.
- Бэкап: GitHub хранит весь текст и историю правок. Аудио — только на сервере, его стоит
  включить в общий бэкап сервера.
